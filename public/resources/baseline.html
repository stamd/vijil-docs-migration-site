Audit baseline

The complete source overview, scope, decisions, and verification limits.

Analysis dated October 28, 2026. This proposal and its supporting tables are in English.

Recommendation: retain Concepts, Agent Owner’s Guide, and Agent Developer’s Guide, and use Diátaxis to govern each page’s purpose. Concepts becomes the canonical home for explanations. AOG covers Console workflows. ADG covers SDK, MCP/plugin, and technical operator tasks; REST remains reference material and a secondary path. Technical Reference stays within ADG, without a fourth tab.

The largest expected gains come from separating mixed content, resolving conflicting definitions, and creating verifiable paths from a task to its relevant contract. Renaming navigation groups alone would not solve these problems.

How to Read This Proposal

  1. Architecture and Diátaxis application: the model, content responsibilities, agent-oriented requirements, and navigation decisions.
  2. Complete proposed TOC: every existing and new target page, with its Diátaxis type.
  3. Page-by-page plan: a separate finding and decision for all 92 existing MDX pages, followed by a detailed registry of 34 proposed new pages.
  4. Evidence and comparison with Dejan’s proposal: concrete inconsistencies, OpenAPI findings, PR #251, and verification limits.
  5. Migration, standards, and checks: PR sequencing, the pilot, redirect policy, templates, ownership, and success criteria.

For spreadsheet work, use migration-map.csv, new-pages.csv, and api-operation-inventory.csv. proposed-navigation.json is a complete Mintlify navigation design, not a deployable change: new page bodies have not been written, and three new pages have explicit publication conditions.

The proposal covers 84 retained existing pages and 34 proposed new pages: 118 MDX pages in the full target model, plus generated REST reference. Of the new pages, 31 have no special product-availability publication condition; three await a confirmed supported workflow: DLP/Defend setup and two Darwin guides. This is neither a recommendation to publish 34 new pages immediately nor a page-count growth target. Most additions extract existing content. After the pilot, verify that each proposed split addresses a real need.

Of the current 92 pages, 17 retain their basic structure, 28 change focus without extracting separate pages, 35 are split, two are substantially rewritten, one is moved, one is moved and split, and eight are retired through PR #251. These are mutually exclusive primary decisions; “keep” includes the specified minor corrections and standard links.

What to Do First

First resolve the contracts that currently yield different answers: Trust Score scale and threshold, Probe/sample_size units, evaluation/engagement/campaign ID relationships, actual capability availability, and monitoring names/scope. Align with PR #251 in parallel. There is no need to block the entire documentation set until every term is agreed; block publication only where content depends on an unresolved contract.

Then run a small Diamond pilot: one Console tutorial, one SDK tutorial, focused run/results guides, an explanation of evidence, and two supporting references. The pilot must demonstrate that a human and an agent can find the right interface, complete the task, and verify its result. Extend the standard to the remaining areas afterward.

Verification and Limits

This is a content and architecture audit of all TOC MDX sources and a structural audit of the OpenAPI group. It does not verify every code example, API response, UI state, or published release through execution. The local working tree, public site, and PR head are not assumed to be identical; their roles are distinguished in evidence-and-dejan.md.

Validation confirmed exactly 92 unique source-page records, eight retirement decisions matching the PR-head TOC, all 34 new-page records with type/placement/origin/acceptance criteria, 118 unique target URLs without a CLI group, and an inventory of all 149 OpenAPI operations. For the same source snapshot, regenerate artifacts with python3 build_audit.py from this directory; after TOC changes, update the editorial map as well. The script only reads docs and writes analytical artifacts here.

The documentation content and docs/docs.json were not modified. The pre-existing local change to developer-guide/getting-started/introduction.mdx was preserved and included in the working-tree review; source hashes and repository state are recorded in source-snapshot.json.
