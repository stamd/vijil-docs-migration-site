Build checks, task success, and meaningful evidence of improvement.

7. CI and Validation

Check What it catches When
TOC/source inventory Every navigated MDX exists; no duplicate URLs; each has an E/H/R/T type and goal Every documentation PR
Frontmatter and descriptions Missing title/description, generic or duplicate candidates, registry scope/version New/changed content; warnings for the unmigrated remainder
Content/link graph Related exists and reaches valid, relevant destinations; type-specific links and exceptions Migrated pages
Terminology lint Confirmed names and prohibited obsolete prose aliases; explicit exceptions for code literals Every documentation PR
Mintlify build and broken links MDX/render/build failures and dead links; pin the appropriate CLI version in CI Every documentation PR
Redirects and anchors No chains/cycles/dead targets; expected legacy anchors and generated routes remain useful Path and TOC changes
OpenAPI schema/coverage Schema validation, unique IDs, public routes, alias decisions, examples, and stable documentation routes Specification synchronization PRs and relevant service releases
Executable examples Imports, complete minimal examples, retained supporting CLI steps, response shapes, statuses, and failure branches Examples changed by the batch; relevant package releases
Rendered Markdown IDs, prerequisites, necessary tab/accordion content, Mermaid, and Related appear in the agent view Pilot, new components, and a representative regression set
Documentation task evaluation Correct interface selection, task completion, valid API/tool calls, and respect for limits Before/after the pilot and significant architectural changes

mint broken-links does not verify semantic destination relevance, score units, or the existence of every SDK method. Vale cannot determine whether a page is a useful how-to. Automation and domain review therefore have different jobs.

Tie executable checks to releases and fixtures. Do not run live production write/deploy workflows for every prose edit. For consequential tasks such as CI gating or tool enforcement, verify failure, timeout, missing results, and shadow/enforce distinctions. For moving already-verified text without changing meaning, build/link/render checks and domain review are sufficient.

8. Measuring Whether Migration Works

Before changing content, save results for the same tasks, queries, and model/tool environment. Repeat them afterward. Traffic is not task success: a crawler fetching ten pages and an agent successfully running an evaluation are different session types.

Measure Proposed assessment
Finding the right destination Short tree test with Console users and developers: first tab/group choice, retrieval success, time, and wrong turns
Agent retrieval Whether relevant H/R destinations are found early; correct product/interface/version selection
Agent task success Completed task with verifiable results, valid IDs, and bounded polling, without invented methods
Contract correctness Correct scale/unit/status; no unverified interchange of evaluation and engagement IDs
Context cost Pages read, tokens required, backtracking, and irrelevant interface content
Maintenance Locations changed for one definition, drift findings per release, and ownership completeness
Human comprehension Whether an owner can explain a finding and next action without reading the SDK catalog

Proposed pilot exit criteria: all critical contract tasks pass without wrong interfaces, statuses, or units; most remaining tasks show shorter or equally short paths with better success. Agree numerical task-success and token-budget thresholds after measuring the baseline, rather than inventing them as evidence of improvement.

agent-evaluation-tasks.json defines 12 initial tasks with expected destinations in the target plan and disallowed incorrect conclusions. It is a documentation evaluation specification, not an executed benchmark or product-functionality test.

The 12 proposed evaluation scenarios

These are evaluation specifications, not executed tests or evidence of product availability.

D01

I have Console access and want to run my first behavioral evaluation of a test Agent.

Expected pages: P029, P044, P045

Pass: Finds the Console tutorial and its result-verification steps.

Fail: Requires Python installation or self-hosting as a mandatory beginner prerequisite.

D02

I want my first complete evaluation from Python. What prerequisites and outputs should I expect?

Expected pages: P054, N021, N019, P089

Pass: One verifiable SDK path with version, credentials/team, and retained Agent/evaluation IDs.

Fail: Mixes the MCP server package, CLI evaluation commands, and SDK configuration formats.

D03

Does a score of 0.72 mean 72, or 0.72 out of 100, and where do I check the threshold?

Expected pages: P007, N003, N012

Pass: Identifies the exact field/interface/scale and separates product verdict from approved release criteria.

Fail: Applies 70 to an SDK field without conversion or promises universal deployment readiness.

D04

Build a CI gate that waits for this particular evaluation and rejects release if the run fails or has no score.

Expected pages: N022, N012, P090, P092

Pass: Uses the SDK, bounded polling, the specific evaluation ID, failure/missing-result handling, and the approved threshold scale.

Fail: Passes because an older Agent score passed or treats every terminal status as success.

D05

A Red Team run is degraded. How do I find the transcript and assess how much to trust its report?

Expected pages: N029, N012, P022, P047

Pass: Preserves the confirmed ID flow, retrieves relevant artifacts, and recognizes partial evidence.

Fail: Equates degraded with complete success or substitutes engagement_id for evaluation_id without a contract.

D06

My local Agent is not publicly deployed. Can I run Red Team testing?

Expected pages: P059, P057, N012

Pass: Distinguishes an authenticated public tunnel from no-tunnel local mode and states their conditions.

Fail: Makes a blanket claim that every local mode does or does not support Red Team.

D07

I need a list of Security Probes and their actual identifiers.

Expected pages: N010, N008, P010

Pass: Uses a visible versioned catalog and IDs; Concepts explains the dimension's meaning.

Fail: Must simulate hover or invent an ID from a display name.

D08

I want to block an unauthorized tool call and prove workload identity. Is a Dome scan sufficient?

Expected pages: N004, N005, P066, P067, N015

Pass: Distinguishes content scans, declarative Controls, and identity-aware Trust Runtime; states framework boundaries.

Fail: Presents an Agent ID or telemetry label as cryptographic identity proof.

D09

ScanResult is flagged but not enforced. How should I interpret the result, redaction, and exec_time?

Expected pages: N014, P069, N013

Pass: Uses the confirmed canonical unit and distinguishes detection, enforcement, sanitized content, and error policy.

Fail: Mixes milliseconds/seconds or claims flagged automatically means the actual request was blocked.

D10

Defend is empty even though Discover scans completed. What should I check?

Expected pages: P049, P027, N028, P051

Pass: Distinguishes scan inventory from dlp runtime events and per-Agent metrics; uses confirmed setup or explicitly identifies missing support.

Fail: Invents an SDK/MCP replacement for CLI-only bootstrap or concludes there are no threats because there are no events.

D11

I want MCP: should I connect Vijil tools to Claude Code, or protect my own MCP server?

Expected pages: N020, P055, P079, P077

Pass: Distinguishes the management server/plugin from the Dome protection proxy and reaches the correct task.

Fail: Confuses servers, credentials, packages, or input/output protection directions.

D12

The SDK has adapt and deploy methods. Can I immediately use Darwin and automatically deploy my application?

Expected pages: N018, P006, P090, P053, N033, N034

Pass: Checks release/deployment availability, distinguishes existing methods from supported workflows, and does not treat conditional pages as availability evidence.

Fail: Infers GA status or supported deployment merely because a method/model exists in reference.
